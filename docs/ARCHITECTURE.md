# Architecture Documentation

Technical architecture of Moss Nexus — the Mossland local-first knowledge & evidence node.

## Design Principles

1. **Indexer, not publisher** — canonical facts live in official repositories; the Qdrant index is a derived, disposable artifact that can always be rebuilt.
2. **Honest locality** — documents, embeddings, and LLM inference run locally. Network touchpoints (model downloads, optional Discord API) are explicit, not hidden.
3. **Never destroy good data** — reindexing goes through a staging collection and an atomic alias swap; the previous index is kept for rollback.
4. **Citations from metadata** — sources are assembled by the backend from retrieval payloads (filename, page, sha256, score), never generated by the LLM.
5. **Fail closed** — unreadable files abort ingestion; low-relevance evidence is discarded; missing evidence yields "not found", not a guess.

## Modules

| Module | Responsibility |
|--------|----------------|
| `src/config.py` | Pydantic settings (.env), security defaults (loopback bind, thresholds, limits) |
| `src/logging_setup.py` | Single loguru configuration; CLI `--log-level` wins; privacy rule: no question text/usernames in logs |
| `src/loaders.py` | PDF (pypdf, per page), MD/TXT (utf-8 → cp949 fallback), DOCX (python-docx); returns `(documents, errors)` |
| `src/splitter.py` | Recursive character splitter (paragraph → line → sentence → word), chunk overlap |
| `src/embeddings.py` | `BGEM3FlagModel` wrapper producing dense (1024-dim) + sparse (token-weight) vectors; device auto-select cuda → mps → cpu |
| `src/ingest.py` | Fail-closed pipeline: load → chunk+hash → embed → staging collection → verify → atomic alias swap → cleanup |
| `src/rag_chain.py` | Hybrid retrieval (dense w/ threshold + sparse → RRF), context assembly, Ollama generation, dependency-level `health()` |
| `src/api.py` | FastAPI: hardened defaults (loopback, CORS, semaphore, timeouts, generic errors, request-ID logging) |
| `src/bot.py` | Discord slash commands, allowlists, cooldowns, message splitting, metadata-based source lines |

## Retrieval Design

**Why hybrid?** BGE-M3 emits both dense semantic vectors and sparse lexical
weights in one pass. Sparse matching is what finds exact strings — contract
addresses, proposal IDs, names — that dense similarity can miss. The two
rankings are fused with Reciprocal Rank Fusion (k=60) in the client.

**Relevance gating.** The dense search applies `MIN_DENSE_SCORE` (cosine,
default 0.35) at the Qdrant level. If neither modality returns evidence, the
LLM is never called and the user gets an honest "not found".

**Qdrant layout.** One collection per ingest run, named
`{alias}__{timestamp}`, with named vectors `dense` (cosine) and `sparse`.
The configured collection name (`moss_knowledge`) is an **alias** that always
points at the latest verified collection:

```
ingest:  create moss_knowledge__20260714120000
         upsert + verify count
         alias moss_knowledge ──▶ moss_knowledge__20260714120000   (atomic)
         keep previous collection, delete older ones
```

Rollback is a single alias update back to the previous collection.

## Prompting & Citations

The system prompt restricts the LLM to the numbered `[Context]` blocks and
asks it to reference evidence as `[1]`, `[2]`. Those numbers map to the
`sources` array that the **backend** returns from retrieval payloads — the
authoritative citation channel. Chunk payloads carry
`content_hash`/`file_hash`/`ingested_at`, the groundwork for the planned
evidence-pipeline (source manifests, revisions, `as_of` queries).

## Concurrency Model

- RAG calls are synchronous (embedding + LLM); interfaces run them in a
  thread pool via `run_in_executor`.
- A global semaphore (`MAX_CONCURRENT_QUERIES`, default 2) protects the local
  LLM; the API adds a queue timeout (429) and a per-query timeout (504).
- The Discord bot has its own semaphore plus per-user cooldowns.

## Performance Notes (qwen3.5:9b, Apple Silicon)

| Operation | Typical |
|-----------|---------|
| Query embedding (BGE-M3, MPS) | 50–150ms |
| Qdrant hybrid search | 10–50ms |
| LLM generation | seconds, model/hardware dependent |

Memory: LLM 6.6GB (9b) or 17GB (27b) + BGE-M3 ~3GB + Qdrant (corpus-dependent).

## Security Model

See [SECURITY.md](../SECURITY.md). Summary: loopback binds everywhere,
`data/` git-ignored, no privileged Discord intents, allowlists + cooldowns,
no question logging, generic user-facing errors, pinned dependencies.
